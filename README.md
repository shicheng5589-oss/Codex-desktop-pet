# Codex 桌宠（CodexPet）

一只贴在 Windows 桌面上的 Live2D 小桌宠：**它跟着 Codex 的实时状态换表情**——
思考中、执行中、等待你、审阅找工具、同步中、被挡住、出错了、完成了、被打断，
一共 9 个状态各有各的表情。眼睛会跟着鼠标转（带惯性和回正动画），旁边有一张任务进度卡片，
右下角三个图标（撤回 / 铅笔 / 橡皮擦）能自己配功能。

> 状态来源是 Codex 自己写在 `~/.codex/` 里的本地记录，**只读、不联网**。

## 特性

* **状态跟着 Codex 走**：读 Codex 的本地会话记录，翻译成 9 个状态；每个状态可以单独指定表情。
* **眼神会跟着你**：按鼠标相对窗口中心的偏移映射，眼睛先动、头慢半拍、身体再慢一点；
  鼠标离开跟随范围会先顿一下再缓入缓出地回正（不是硬拽回去）。
* **表情不是死的**：每个状态有一“池”表情，隔一会儿换个心情；有 40+ 个表情可逐条开关，
  道具/贴纸类表情可以整体屏蔽。
* **任务进度卡片**：显示当前任务名、已用时、工具调用数、上下文用量；两种外观（半透明毛玻璃 / 实色）。
* **底部三个图标可编程**：撤回 / 铅笔 / 橡皮擦，每个的**单击**和**右键**都能配功能
  （打开设置、切编辑模式、撤销表情、清空卡片、隐藏到托盘、静音动画…… 或者 Codex 联动那套）。
* **图标按图上的实际位置命中**，点画纸空白处不会串格。
* **四种互动**：摸头（脸红/爱心眼）、双击换表情、拖动搬家、滚轮缩放（12%–160%）。
* **跟随虚拟桌面**：切桌面时它跟着过去，不会“看不见”。
* **纯本地**：不联网、不读密钥、日志自动截断。

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | **Windows 10 1809 以上 / Windows 11**（详见[兼容性与适配](#兼容性与适配)） |
| Python | **64 位 CPython 3.12**（`vendor/` 里的二进制是按 3.12 编译的） |
| 运行时 | **Microsoft Edge WebView2 Runtime**（Win11 自带；Win10 一般随 Edge 装好，没有的话[点这里装](https://developer.microsoft.com/microsoft-edge/webview2/)） |
| 权限 | 普通用户即可，**不需要管理员**，不写注册表敏感项、不装驱动 |
| 网络 | 不需要（只有 `127.0.0.1` 上的一个本地网页服务，用来把界面喂给 WebView2） |

Python 依赖（`pythonnet` 等）**已经放在 `vendor/` 里**，开箱即用；
如果你想自己装，见 `requirements.txt`。

## 安装与启动

1. 把整个文件夹放到一个不会被误删的位置（比如 `D:\CodexPet`）。
2. 确认 `pythonw.exe` 能被找到，二选一：
   * 把 Python 的安装目录加进 `PATH`；
   * 或设一个环境变量 `CODEXPET_PYTHON` 指向 `python.exe` 的完整路径。
3. 双击 **`启动桌宠.cmd`**（能看到报错）或 **`启动桌宠.vbs`**（无黑框）。形象会出现在屏幕右下角。
4. 想要桌面快捷方式：右键 `启动桌宠.vbs` → 发送到 → 桌面快捷方式。

其它脚本：

| 脚本 | 作用 |
| --- | --- |
| `停止桌宠.cmd` / `重启桌宠.cmd` | 关闭 / 关闭再启动 |
| `诊断.cmd` | 自检一次（约 25 秒），把日志打出来并导出 `selftest.png` |
| `开机自启-开启.cmd` / `-关闭.cmd` | 登录 Windows 自动启动 |
| `跟随Codex启动-开启.cmd` / `-关闭.cmd` | Codex 一开，桌宠跟着开（后台每 4 秒看一眼进程） |
| `清理缓存-释放空间.cmd` | 删掉 WebView2 缓存（通常 200–400MB），下次启动自动重建 |
| `恢复道具动画.cmd` | 把模型里被屏蔽的“道具动画”（锤子/猫手/泡泡…）恢复回来 |
| `黑边处理-新旧版切换.cmd` | 缩放后偶尔残留黑边时，切换两套重画强度（详见常见问题） |

> 想彻底卸载：先 `停止桌宠.cmd`，再删掉整个文件夹；如果开过开机自启/跟随启动，
> 顺便删掉 `shell:startup` 里那两个快捷方式，或在设置里把开关关掉再保存一次。

## 设置项一览

设置窗口里分 7 栏，**每一栏标题右边都有一个 ↻ 圆圈按钮 = 只把这一栏恢复默认**，
右下角还有整页的「恢复默认」。改完点「保存并应用」才生效（不想改就点「放弃更改」）。

| 栏 | 内容 |
| --- | --- |
| **外观** | 桌宠大小（12%–160%）、不透明度、视线跟随范围、自动切换表情、自动动作/闲置表演、始终置顶、显示状态小标签、**渲染帧率上限**（30/60/90/120/144/165/240 帧或不限制，旁边实时显示当前 fps） |
| **行为** | 进度卡片外观（半透明+模糊 / 实色）、卡片与桌宠间距、卡片跟着桌宠放大、跟随虚拟桌面、**开机自动启动**、**跟随 Codex 启动**、滚轮缩放开关、卡片毛玻璃开关 |
| **底部按钮与功能方案** | 方案一（桌宠编辑）/ 方案二（Codex 联动）；每个图标的**单击 / 右键**各选一个功能 |
| **状态对应的表情** | 9 个状态各选一个表情（模型里 40+ 个随你挑） |
| **表情白名单** | 逐条勾选哪些表情允许出现（不想要的贴纸/道具类取消勾选） |
| **动作与表情播放** | 表情最短保持时间、换表情概率、顺带做动作的概率、闲置动作间隔、动作逐条开关、动作间隔 |
| **排查** | 记录鼠标事件到日志、打开日志、清空日志、打开程序文件夹、重新载入形象、退出桌宠 |

> 「开机自动启动」和「跟随 Codex 启动」这两行字是**微红色**的，提醒你注意：
> 前者会往启动文件夹放快捷方式，后者会常驻一个每 4 秒轮询的隐藏 PowerShell。

## 性能实测

下面这组数字是**在作者机器上实测**的，不是估算：

> 测试机：Windows 11 25H2（Build 26200）/ 20 逻辑核 / 屏幕 2560×1600 @150% 缩放 /
> 桌宠缩放 100%（窗口 600×930 物理像素）/ 空闲（不动鼠标、不做动作）。

### CPU

| 项目 | 实测 |
| --- | --- |
| 空闲 CPU | 15 秒采样只花掉 **0.41 秒 CPU** ≈ **单核 2.7%**、整机（20 核）**0.14%** |
| 渲染帧率 | 由设置里的「渲染帧率上限」决定，**默认 60 帧**；实测把上限设成 30 / 90 / 60 时，实际渲染帧数分别是 **29 / 86 / 59 fps**，设成"不限制"时 **149 fps**（跟着屏幕刷新率走） |
| 拖动 / 缩放瞬间 | 短时升高：拖动时每秒约 60 次窗口移动（日志实测 63 次/秒）；停止即回落 |

> 帧率上限越高越顺滑，也越费电。60 帧在 60Hz 屏上已经足够；
> 120/144/165/240Hz 屏想更丝滑就往上调，"不限制"= 跑满屏幕刷新率。
> 设置里那一行会显示**当前实际帧率**，改完 3 秒内就能看到效果。

### 内存（任务管理器里整棵树）

| 进程 | 占用 |
| --- | --- |
| `pythonw.exe`（宿主：窗口、鼠标、状态翻译） | **约 104 MB** |
| `msedgewebview2.exe` ×3（浏览器主进程 + 渲染 + GPU） | **约 178 MB**（125 / 39 / 14 MB） |
| **合计** | **约 282 MB** |

> 说明：大头是 WebView2（相当于一个精简版 Edge）。模型贴图是固定的两张（2048 / 1024），
> 缩放不会重新上传纹理，所以缩放大小对内存影响有限。关闭桌宠后这些内存全部释放；
> 屏幕高度有限时，放大上限会自动收（见下一节）。

### 磁盘

| 项目 | 占用 |
| --- | --- |
| 程序本体（`run.py` + `web/` 界面与模型 + 脚本 + 文档） | 约 **15 MB** |
| `vendor/`（Python 依赖，可删改走 pip） | 约 **24 MB** |
| `web/model_backup_props/`（道具动画备份，恢复用） | 约 **4.3 MB** |
| `.webview2/`（运行期浏览器缓存，**可清**） | **200–400 MB**（实测 372 MB） |
| `pet.log` | 每天几 KB，**超过 512KB 自动只留最近 300 行** |

> 想省空间：双击 `清理缓存-释放空间.cmd`；
> 想省内存：不用的时候 `停止桌宠.cmd`（或右键 → 退出桌宠）。

### 启动耗时

日志实测：`服务启动 → 窗口创建 → WebView2 就绪 → 界面就绪` 都在**同一秒内**（约 1 秒），
首帧渲染紧随其后；不需要预热。

## 兼容性与适配

### Windows 版本

| 系统 | 支持情况 | 说明 |
| --- | --- | --- |
| **Windows 11**（21H2 – 25H2） | ✅ **实测可用**（作者用 25H2 / Build 26200） | 圆角走系统 DWM；毛玻璃走 `SetWindowCompositionAttribute`（需要系统「透明效果」开着） |
| **Windows 10**（1809 – 22H2） | ✅ 可用 | 没有 DWM 圆角接口时自动退回 `Region` 裁剪（日志会写「改用 Region 裁剪」）；毛玻璃需要系统透明效果，否则只有半透明 |
| Windows 10 早期版本 / 8.1 / 7 | ❌ 不建议 | WebView2 与 per-monitor DPI v2 都缺；界面会异常 |
| Windows Server / LTSC | ⚠️ 未测试 | 需要自行装 WebView2 Runtime |

其它平台（macOS / Linux）：不支持，整套实现依赖 Win32 分层窗口 + WebView2。

### 分辨率与 DPI 适配

窗口逻辑尺寸固定 **400×620**，实际像素 = `400×620 × DPI缩放 × 桌宠缩放`，
内容按比例渲染（矢量 + Live2D，不糊）。常见组合：

| 屏幕 / DPI | 桌宠缩放 50% | 100% | 160%（上限） |
| --- | --- | --- | --- |
| 1920×1080 @100% | 200×310 | 400×620 | 640×992 |
| 2560×1440 @125% | 250×388 | 500×775 | 800×1240 |
| 2560×1600 @150% | 300×465 | 600×930 | 960×1488 |
| 3840×2160 @200% | 400×620 | 800×1240 | 1280×1984 |

* **放大上限自动算**：默认给到 **160%**，但如果屏幕不够高会往下收
  （允许窗口比屏幕高出 20%，因为窗口上方那块是空的、留给进度卡片，角色贴着底边画）。
  实测：2560×1600 / 2560×1440 / 1920×1080 都能到 160%；1366×768 约 147%；1280×720 约 137%。
* **缩小下限**：约 12%（比桌面图标略大一点）。
* **DPI 在启动时读取一次**：把桌宠拖到另一块**不同缩放比例**的显示器上，或者中途改了系统缩放，
  大小不会自动重算 —— **重启一次桌宠**即可（已知限制）。
* **多显示器**：可以放在任意显示器上；会跟着当前显示器的工作区摆放（避开任务栏）；
  缩放以窗口中心为锚点，不会“飞走”。
* **远程桌面 / 虚拟机**：能跑，但透明窗口 + GPU 合成在部分虚拟显卡上会退化成半透明或残留黑边
  （见常见问题里的重画处理）。

### 其它适配细节

* **高刷屏**：帧率上限可以按屏幕来配（60 / 90 / 120 / 144 / 165 / 240 或不限制），
  默认 60 帧；帧率越高 CPU 越高（60 帧时空闲仍 <3% 单核），觉得费电就往低调。
* **多虚拟桌面**：跟随切换（用系统的虚拟桌面 COM 接口），不会留在看不见的桌面上。
* **单实例**：重复启动不会有第二只（靠命名互斥量拦住）；想换新代码要 `重启桌宠.cmd`。
* **虚拟桌面 / 锁屏 / 休眠**：休眠唤醒后如果发现位置或大小不对，重启一次即可。

## 常见问题

**双击启动没反应？**
先看是不是已经有桌宠在跑（任务栏没有它，看任务管理器里的 `pythonw.exe`）；
再双击 `诊断.cmd`，它会自检并打印 `pet.log` 的最后部分，里面通常直接写着原因。

**滚轮缩放后偶尔残留一块黑边？**
这是 Win11 对“挖空背景的透明分层窗口”改尺寸时的老毛病（切一下别的窗口也会自己掉）。
程序每次改完尺寸会自动连着重画 9 次（约 1.2 秒），把概率压得很低；
万一还留着：**右键桌宠 → 重画窗口**。想换回更保守的重画策略，双击 `黑边处理-新旧版切换.cmd`。

**提示 WebView2 初始化失败？**
装一下 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)；
如果已经装了，双击 `清理缓存-释放空间.cmd` 清掉损坏的缓存再启动。

**点「设置…」没反应 / 设置窗口打不开？**
设置窗口会置顶、并在任务栏留一个图标，找不到时点任务栏那个；
它跑在独立线程上，日志里会写 `打开设置窗口…` / `设置窗口 WebView2 就绪…`。

**拖动很卡？**
拖动是 15ms 一个的 UI 定时器直接搬窗口，正常跟手；如果卡，通常是显卡驱动让分层窗口合成变慢，
可以试试把「卡片毛玻璃」关掉，或在设置里关掉「鼠标滚轮缩放桌宠」。

**怎么让它别出现在屏幕上？**
右键 → 更多功能里可以「隐藏到系统托盘」（可配到某个图标上），或者直接 `停止桌宠.cmd`。

## 隐私与安全

这个程序**不联网、不上传任何东西**（只有 `127.0.0.1` 上一个随机端口的本地网页服务，
用来把界面喂给 WebView2；不监听局域网）。它读的东西只有两类：

1. **Codex 自己写的本地记录**（全部**只读**打开，SQLite 用 `mode=ro`，绝不写入）：
   * `~/.codex/thread_history_1.sqlite` —— 每个回合的状态、步骤类型与时间
   * `~/.codex/state_5.sqlite` —— 任务标题、工作目录、token 用量
   * `~/.codex/sessions/**/*.jsonl` —— 事件流，用来判断某个工具是否还在跑
2. **自己的设置与位置**：`pet_settings.json`、`pet_position.json`（都在本目录里）。

隐私相关的几个细节：

* 状态翻译时**只取**任务名、工具名、类型、时间等字段；命令行里的
  `key / token / secret / password / authorization / cookie` 之类字段会被跳过，不写进卡片，也不写日志。
* 日志默认**不记录鼠标事件**（要在设置里勾「记录鼠标事件到日志」才写），
  平时只有启动信息、设置变更、每分钟一行帧率、以及报错；超过 512KB 自动截断。
* 卡片上显示的“上下文用量”是 Codex 自己记录的 token 百分比数字，不是内容。
* 想确认没有联网行为：看 `run.py` 里的 `start_server()`（只绑 `127.0.0.1`）；
  也可以用防火墙/抓包工具盯一下。

## 换成你自己的 Live2D 模型

模型放在 `web/model/`，入口是 `web/model/settings.json`（就是 Live2D 的 `*.model3.json` 格式，
只是换了个名字）。最小可用长这样：

```json
{
  "Version": 3,
  "FileReferences": {
    "Moc": "你的模型.moc3",
    "Textures": ["textures/texture_00.png"],
    "Physics": "你的模型.physics3.json",
    "DisplayInfo": "你的模型.cdi3.json",
    "Motions": {
      "Idle": [{ "File": "motions/idle.motion3.json", "FadeInTime": 0.6, "FadeOutTime": 0.6 }]
    },
    "Expressions": [
      { "Name": "开心兴奋", "File": "expressions/开心.exp3.json" }
    ]
  }
}
```

* `Motions` 里的组名建议保留 `Idle`（闲置循环）和 `Show`（表演）；设置窗口会把它们列出来。
* `Expressions` 里的 `Name` 就是设置里「状态对应的表情 / 表情白名单」显示的名字。
* 只支持 **Cubism 4**（`.moc3`）模型；Cubism 2 不支持。
* 换了模型后，桌宠的三处尺寸常量（`run.py` 顶部 `WINDOW_W / WINDOW_H / CHAR_BASE_H`）
  和“底部三个图标”的命中比例（`TOOL_MARK_X / TOOL_MARK_Y`）需要按你的构图微调。
