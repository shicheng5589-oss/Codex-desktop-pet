# Codex 桌宠（DeepSeek 鼠控版 Live2D）

一个贴在 Windows 桌面上的 Live2D 小宠物：它读的是 **Codex 自己的实时状态**，
所以 Agent 在思考、执行、等你确认，还是已经做完，你一眼就能看出来 —— 不用切回 Codex 窗口。

> **这份文件是工程实现笔记**，记录了这个桌宠是怎么做出来的、踩过哪些坑、怎么调试。
> 面向使用者的说明请看仓库根目录的 **[README.md](../README.md)**（安装、设置、性能、兼容性、常见问题都在那里）。

## 怎么用

1. 双击桌面上的 **「Codex 桌宠」** 快捷方式（或双击 `启动桌宠.vbs`，都不会弹黑框）。
2. 形象出现在屏幕右下角，站在最上层、不占任务栏。**窗口只有角色那么大**，不会挡住别的东西。
3. 操作方式（都可以在设置里调，见下）：

   | 操作 | 效果 |
   | --- | --- |
   | 鼠标靠近 | **眼睛 + 头部跟着你的鼠标转**，按"相对窗口中心的偏移比例"映射（不是固定像素偏移） |
   | **左键单击** | **摸头**：优先判定头部区域，会脸红 / 爱心眼，还会做个动作 |
   | **左键双击** | **换表情**：在模型的表情里循环切换，弹一个小提示告诉你换了哪个 |
   | 点在**底部三个图标**上 | 触发那里配好的功能（**单击**触发；双击也按单击算），右键则是那一项配的右键功能 —— 见下一节 |
   | **左键按住拖动** | 移动窗口（位移超过 5 px 才算拖动），每一次真实鼠标移动搬一次窗口，跟手不卡 |
   | **右键单击** | 弹出菜单：进度卡片 / 摸头 / 换表情 / 随机动作 / 设置 / 切到 Codex / 重新载入 / 退出 |
   | **右键按住拖动** | 也是移动窗口，并且**不会**弹出系统菜单 |
   | **鼠标滚轮** | 直接在角色上滚动 = 缩放桌宠，以窗口中心为锚点，不会跑偏 |
   | 点在透明边角 | 直接穿过去，不挡你点别的东西 |
   | 盯着它看几秒 | 偶尔会害羞（脸红 / 心跳） |

   > 右键菜单只有**点在角色像素上**才会弹 —— 点在透明处会穿过去，弹的是桌面自己的菜单，不会两个一起冒出来。

   > 只有**点在角色身上**才算互动；点在它周围的透明区域会直接穿过去，不会挡住你点别的东西。
   > 进度卡片是纯展示，所有按钮都在设置窗口里 —— 因为透明窗口是"分层窗口"，网页收不到鼠标点击，
   > 所以点击/拖动是桌宠程序自己读鼠标状态来处理的（这也是它现在能正常拖动的原因）。

   > **拖动实现说明**（试过三条路，最后一条才对）：
   > ① 独立线程按 144 Hz 调 `SetWindowPos`：分层窗口 + WebView2 反复合成，把系统鼠标都拖死；
   > ② `ReleaseCapture()` + `WM_NCLBUTTONDOWN/HTCAPTION` 交给系统移动循环：在这个窗口上会立刻返回（日志 `0.00s`）；
   > ③ 靠 `MouseMove` 事件搬窗口：这类窗口里鼠标移动事件可能只送到一两帧，所以拖不动。
   >
   > 现在用的是：**一个 15ms 的 UI 定时器**，每帧读"光标现在在哪 + 按键还按着吗"，
   > 直接算出窗口应有的位置（不依赖鼠标移动事件，也不起工作线程）。松手立即停止。
   > `pet.log` 会记录每次拖动的：用时、搬动次数与速率、窗口位置变化、渲染 FPS。

## 底部三个按钮：撤回 / 铅笔 / 橡皮擦

设置里新增独立的 **「底部按钮」** 分类，可选择两套方案，并为每个按钮的
**单击 / 右键**分别指定功能；每一项都有 **「无功能」**。

> 触发方式换过一次手：最早是单击，中间短暂试过双击，2026-09-25 起**又改回单击**
> （双击手感不好）。设置里现在只有「单击 / 右键」两列；换回单击时，原来配在双击上的
> 功能会自动搬到单击上，不用重新配（老配置文件迁移一次就会记下来，不会反复覆盖）。
> 图标上双击也不会变成没反应 —— 它会按单击处理。

* **方案一：桌宠编辑 / 恢复 / 清理**——打开设置、编辑模式、锁定位置、恢复默认、撤销表情、
  清空进度卡片、隐藏到系统托盘、暂时静音动画。
* **方案二：Codex 联动**——新建会话、切到 Codex、复制新任务名、把备注写入 Codex 输入框、
  打断任务、撤回输入、用新空白会话清空上下文、关闭 Codex 窗口。

所有功能触发后都会先弹出 **确认框**，只有点击「是 / 确认」才真正执行。
三个图标按**画在图上的实际位置**命中（撤回 ≈ 角色宽度 35%、铅笔 ≈ 46%、橡皮擦 ≈ 56%，
纵向在角色高度的 ~0.70–0.85 那一条）。点击图标不会误触发摸头、换表情或普通右键菜单；
点画纸空白处、写字板或身体则还是桌宠自己的反应。

> 之前的命中区是"把角色宽度三等分"，可那三个图标挤在中间偏左，
> 于是点最左边的**撤回**会落进中间那一格，弹出"铅笔：未配置功能"——现在按实测位置命中，不会再串格。
## 进度卡片：画在桌宠窗口里（宽度固定、高度自适应）

卡片**直接画在桌宠自己的网页里**（一个 div），不再单独开窗口：

* **尺寸**：宽度 CSS 固定 372px，**高度 `auto` 由内容撑开**（标题、数据行、正在做什么、最近一句话）。
  桌宠窗口尺寸**永远不变** —— 没有改窗口尺寸的卡顿，也不影响点击穿透。
* **位置**：固定在桌宠窗口上方、水平居中；打开时角色自动缩小一点腾位置（只改模型缩放，不动窗口）。
  * 新版改成**贴着"角色头顶"定位**：桌宠放大缩小时，卡片与头顶的距离**保持不变**。
    以前是贴窗口顶部，一放大中间就空出一大段，看着像卡片飘走了。
  * 默认间距 **12px**，设置里可调 **-20–60px**；负数会让卡片稍微压进头顶上方的留白，适合更紧凑的构图。
  * 卡片字号/内边距会**跟着桌宠一起缩放**（1.4 倍桌宠时卡片约 1.24 倍），
    大桌宠不会配一张小卡片；不想要可以在设置里关掉「卡片跟着桌宠一起放大」。
* **圆角**：`border-radius: 16px` 加在**最外层** `.card-bg` 上，并且 `overflow: hidden` +
  `clip-path: inset(0 round 16px)` 强制裁剪，圆角外是**真正的透明像素**（桌面壁纸直接透出来）。
  实测：深色 / 浅色背景下四个角都干净（截图取色确认，圆角外是背景而不是卡片底色）。
* **两种外观，可以随时切着对比**（设置 → 进度卡片外观，切完立刻生效）：
  * **最初版本：半透明 + 模糊浮层** —— `rgba(18,22,33,0.88)` + `backdrop-filter: blur(6px)` +
    16px 圆角 + 柔和投影，就是第一版的观感。
    （提醒一句原理：桌宠窗口是"色键透明"，窗口内的半透明像素会和键色有一点点混色，
    所以它看起来会比独立窗口那版稍微"灰"一点 —— 这是这套透明方案的固有代价。）
  * **简洁版：实色卡片** —— 完全不串色，颜色最准，代价是没有半透明感。
* **不会压住角色**：卡片高度由内容撑开，角色缩放按**卡片实测高度**来算；
  窗口比较小时卡片自动转紧凑（只留状态 + 任务名），窗口极小（< 180px 高）时干脆不显示并提示。
  实测三种窗口尺寸下都**没有重叠**。
* 进度卡片固定使用当前已验证稳定的“画在桌宠窗口里”方式；原来的“渲染方式”选项已经移除。
* 打开方式：**右键桌宠 → 显示 / 隐藏任务进度**，或者设置窗口里的「展开 / 收起进度卡片」。

   卡片里的「打开 Codex」会把你正在用的 Codex 窗口切到前台（按进程识别，不依赖窗口标题）。

## 设置窗口

双击桌宠就能打开，也可以右键 → **设置…**。改完点右下角「保存并应用」才生效（想放弃就点「放弃更改」）：

* **每一栏标题右边的圆圈按钮（↻）**：只把这一栏恢复默认；整页恢复默认在右下角。
* **微红色的两项**（**开机自动启动** / **跟随 Codex 启动**）是特意标出来提醒你别乱关的；
  它们现在保存后真的会生效（开机自启 = 往启动文件夹放一个快捷方式，跟随 Codex = 随 Codex 一起拉起桌宠）。

* **外观**：
  * **桌宠大小**：从"桌面图标那么大"到 **160%**（屏幕矮的机器会按屏幕高度兜底），
    滑条两端会显示当前机器的实际范围
  * **不透明度**：40%–100%
  * **视线跟随范围**：0（关闭）到 1200 px，默认 320 px
  * **表情自动切换速度**：2–60 秒换一次
  * 是否始终置顶、是否显示状态小标签
  * 提示：**鼠标滚轮**也能直接缩放，不用每次开设置
* **行为**：是否跟随虚拟桌面、是否开机自动启动、是否**跟随 Codex 启动**；一键「展开 / 收起进度卡片」「让它做个动作」
  「回到右下角」「切到 Codex 窗口」
* **状态对应的表情**：9 个状态各自用一个下拉框选表情（模型里的 40 多个表情都能选），改完立刻换
* **排查**：打开运行日志、打开程序文件夹、重新载入形象、退出桌宠、恢复默认

设置存在 `pet_settings.json` 里，删掉它就回到默认。

关掉桌宠：右键 → 更多 → 退出桌宠，或者双击 `停止桌宠.cmd`。
想重启（改完设置想让它彻底重来）：双击 `重启桌宠.cmd`。

## 它不是一个只会按状态摆表情的木头

### 这个模型里有多少东西

* **表情 44 个**（`.exp3.json`），状态映射 + 随机心情都用它。
* **动作 8 个**，分三组：

  | 组 | 动作 | 时长 |
  | --- | --- | --- |
  | Idle（闲置） | idle.motion3.json | 4.0s |
  | Idle（闲置） | aidale.motion3.json | 4.8s |
  | Tap（被戳） | 自拍简单 | 1.3s |
  | Tap（被戳） | 开盖 | 1.0s |
  | Tap（被戳） | 喷水 | 0.5s |
  | Tap（被戳） | chuipaopao（吹泡泡） | 5.0s |
  | Show（表演） | 自拍 | 3.3s |
  | Show（表演） | 番茄酱 | 5.0s |

  > 这些动作文件里都标着 `Loop=True`，尤其那个 **4 秒的 idle 本身就是一段"表演"**
  > （砸头 / 吹泡泡 / 自拍这些都在里面），所以它会 4 秒一轮不停地重播 ——
  > 之前你看到"老是重复同一个画面"就是这个原因。

### 播放规则现在都能调

设置 → **动作与表情播放**：

* **自动切换表情**——关闭后只显示“状态对应的表情”，不会再随机换脸。
* **表情最短保持时间**（2–60 秒）—— 到点后才允许考虑切换；再配合“到点后真的换表情的概率”控制频率。
* **顺带做个动作的概率**（0–100%）—— 换表情时顺便播一个动作的几率。
* **自动播放动作 / 闲置表演**——关闭后会立即停止正在播放的循环动作，保持呼吸/物理但不主动表演；
  **闲置动作间隔**（0–120 秒，**0 = 完全不做闲置动作**）是它开启时的补充控制。
* **动作白名单**：8 个动作逐条勾选（带组名和时长），**不想看的直接取消勾选**，
  比如把 `Idle · idle.motion3.json` 关掉，就再也不会砸头/吹泡泡了。
  还有「全选动作 / 全部关掉」两个按钮。
* **动作最小间隔**（0–60 秒）—— 两次动作之间至少隔这么久，避免连播。

### 表情也能逐条关掉（重要）

**先说结论**：那个"大锤砸头"其实是**藏在 `idle.motion3.json` 这段闲置动作里的道具动画**。
这个文件有 89 条曲线，其中 **75 条是道具曲线**（`maoshou2..7`、`j2..j7` …），
也就是这段 4 秒动画本身在轮播一堆道具/特效。所以：

* **关表情白名单没用**（它不在表情里）；
* **正确做法**：设置 → **动作白名单** → 取消勾选 **`Idle · idle`**（那条 4 秒的表演），
  只留 `Idle · aidale`（它只有 5 条道具曲线，安静得多）；
* 或者干脆按 **「让它安静点（只保留呼吸）」**：一键关闭自动表情、自动动作和视线/头部跟随，
  停掉正在循环的动作，只保留状态表情与呼吸/物理。

设置里的**表情白名单**仍然有用 —— 这个模型的表情里有不少也是"道具 / 贴纸"类型
（只改一个自定义参数就冒出一个道具，比如 `晕晕`、`吐魂`、`流汗`、`问号`、各种贴纸）：
不想要的在那里取消勾选，状态映射、随机心情、双击换表情都会跳过它。

### 道具动画已经移除

初次制作时无法稳定解决锤子重复问题，因此锤子及相关道具曲线已经从动作文件中删除。
原来的「道具屏蔽」设置也一并移除；需要恢复历史道具动画时，仍可使用
`restore_props.py` / `恢复道具动画.cmd` 从备份中恢复。

### 设置改成"点保存才生效"

设置窗口底部现在是：**放弃更改 / 保存并应用 / 恢复默认**，改动的控件会显示
`● 有未保存的更改`，按 **Ctrl+S** 也能保存。桌面上的「保存并应用」按钮在没改动时是灰的。
「让它安静点」「恢复默认」这类按钮也只是**填好表单**，同样要点保存才真正生效。

> 设置窗口顶部现在有一行**实时状态**：
> `桌宠此刻：表情 X · 最近动作 Idle:0 · 白名单已允许 动作 5/8、表情 41/44`
> ——改完设置对照这一行，就能确认到底生效了没有、以及那个讨厌的画面来自哪一个动作。

* 白名单里列出**全部 44 个表情**，取消勾选 = 再也不会出现（状态映射、随机心情、双击换表情都会跳过它）。
* 也有「全部允许 / 一个都不换」两个按钮。
* 同一个页面里「状态对应的表情」下拉框现在能正常列出 44 个表情了 ——
  之前显示"找到 0 个表情"、下拉只有「不改变表情」是**读取路径的 bug**（表情声明搬进
  `FileReferences` 之后，读取代码还在读外层），已修。

* **眼神跟随（按比例映射）**：把鼠标相对**窗口中心**的偏移换算成比例
  `ratio = 偏移 / (窗口宽或高 ÷ 2)`，夹在 `[-1, 1]` 后写进 `ParamEyeBallX/Y` 和 `ParamAngleX/Y`
  —— 鼠标移到窗口边缘时眼珠正好到极限，窗口大小怎么变都对应得上。
* **死区**：比例绝对值小于 `0.1` 时不动，避免手抖眼珠乱颤。
* **平滑**：每帧向目标靠近 10%（Lerp），眼神是"滑"过去的，不是瞬移。
* **范围限制**：超出设定的跟随范围（默认 320 px）就回到中位，不会隔着半个屏幕盯着你看。
* **缩放即同步**：窗口一变大变小，网页下一帧就用新的宽高当分母，同时 Live2D 会收到窗口尺寸变化重新布局。
* **随机心情**：开启“自动切换表情”后，每个状态都有一“池”表情（比如执行中是「开心兴奋 / 喵喵手 / 星星眼 / 调皮 / 魔爪」）；
  关闭后只显示状态对应表情，避免表情频繁跳变。
* **拖动反应**：开始拖的时候随机切换心情（开心、调皮、害羞、生气…），放下之后再补一个反应。
* **戳一下**：单击展开进度卡片时会顺手做个动作、换个表情。
* **被盯着看**：鼠标停在它身上超过几秒，偶尔会脸红或心跳。

## 缩放与大小限制

* **鼠标滚轮**：光标在角色身上滚动即可缩放；也可以在设置里拖「桌宠大小」滑条。
* **锚点**：缩放以**窗口中心**为锚点，不会缩放时"飞走"。
* **范围**：最小 **48×48 像素**（桌面图标大小），最大 **160%**。
  （窗口允许比屏幕高出 20% —— 上方那块是空的、留给进度卡片，角色本身贴着底边画；
  屏幕特别矮的机器会按屏幕高度自动往回收一点。）设置界面里的滑条两端就是按你屏幕算出来的实际百分比。
* **冲突保护**：缩放的 0.45 秒内不接受拖动，避免"又缩又拖"打架。

> 顺带一提：透明窗口 + 网页控件在 Windows 上有个坑 —— 鼠标点击会落在窗口本身、传不到网页里。
> 所以桌宠是"程序自己盯着鼠标"来判断你在点它、拖它的，网页只负责演。这样不管系统怎么变都能用。

这些都在 `web/pet.js` 顶部：`MOOD_POOLS`（每个状态的表情池）、`DRAG_MOODS` / `DROP_MOODS` /
`POKE_MOODS` / `SHY_MOODS`，想加表情往数组里填名字就行。

> 如果快捷方式或 `启动桌宠.vbs` 没反应，改用 **`启动桌宠.cmd`** —— 它会显示找不到 Python 之类的具体原因；
> 也可以用 **`诊断.cmd`** 自查。

## 在别的桌面也能看到

桌宠会自动跟着你在 Windows 虚拟桌面之间移动：你按 `Win + Ctrl + ←/→` 换桌面，
它会跟过去继续待在最上层并显示最新进度。

> 用的是系统自带的虚拟桌面接口（IVirtualDesktopManager）。如果你的系统策略把这个接口关掉了，
> 桌宠会留在原来的桌面（`pet.log` 里会写一句提示），其他功能不受影响。

## 它怎么知道 Codex 在干什么

只读 Codex 自己写的本地文件，不联网、不上传：

* `~/.codex/thread_history_1.sqlite` —— 每个回合的状态（进行中 / 已完成 / 被打断）、每个步骤的类型和时间
* `~/.codex/state_5.sqlite` —— 任务标题、工作目录、token 用量
* `~/.codex/sessions/**/*.jsonl` —— 事件流，用来判断某个工具是否还在跑

桌宠只挑你最近那个"用户任务"，内部子任务（例如安全审阅）不会顶掉它。

## 换形象 / 改状态映射

* 模型放在 `web/model/`，`settings.json` 是给渲染器看的清单（动作组 + 44 个表情）。
* 想换模型：把新的 Live2D（Cubism 3/4）模型文件夹放进来，改 `web/model/settings.json` 里的
  `FileReferences` / `Motions` / `Expressions` 路径即可。
* 状态→表情的对应表在 `web/pet.js` 顶部的 `STATE_STYLE`，改 `expr` / `motion` 就能换成别的表情。
* 桌宠窗口宽高在 `run.py` 的 `WINDOW_W` / `WINDOW_H`（单位是 CSS 像素，程序会按屏幕缩放自动换算）。

## 排查

* 双击 **`诊断.cmd`**：会启动一次自检，把 `pet.log` 打出来，并导出一张 `selftest.png`。
* **点「设置…」没反应？** 现在设置窗口会：① **置顶**显示（不会被 Codex 窗口压住）；
  ② 在**任务栏**留一个图标（找不到时可以点出来）；③ **自动搬到你现在看的虚拟桌面**
  （新窗口默认开在"进程启动时那个桌面"，切过桌面就会看不见 —— 这是之前那个 bug 的原因）。
  ④ 设置窗口跑在**独立的 STA 线程**上 —— 之前它是在右键菜单回调里直接建的，
  那条路径上线程被当成 MTA，WebView2 会报
  `RPC_E_CHANGED_MODE：无法在设置线程模式后对其加以更改`（就是那个弹窗）。
  日志里会写 `打开设置窗口…` / `设置窗口 WebView2 就绪…` / `设置窗口初始化失败…`，一看就知道卡在哪一步。
* 日志文件：`pet.log`（每次启动都会追加），里面会记录：
  * 鼠标事件（`鼠标事件：pat (123,456)` 这种），能看出点到底有没有被识别
  * 每次拖动：用时、**搬动次数与速率**、位置变化、渲染 FPS
  * 渲染 FPS：约每分钟一条（含窗口尺寸和缩放）
  * 页面加载、WebView2 初始化结果、设置变更
  * **未捕获异常**：桌宠是 `pythonw` 启动的（没有控制台），异常以前会凭空消失，
    现在会连同堆栈一起写进日志 —— 出问题时先看这里
* **滚轮缩放后偶尔留一块黑边？** 这是 Win11 对"挖空背景的透明窗口"改尺寸时不重画旧区域的
  老毛病（切一下别的窗口、拖一下桌宠也会自己掉）。现在每次改完尺寸都会自动连着重画几次
  （约 1.2 秒内 9 次，最后一轮还会把窗口抖 1px 逼系统重新合成），把概率压得很低；
  万一还留着，**右键桌宠 → 重画窗口（缩放后出现黑边时点一下）** 立刻就能清掉。
  觉得新补救反而更糟的话，双击 **`黑边处理-新旧版切换.cmd`** 可以退回上一版的做法
  （重画 6 次、固定 50ms、不抖窗口），再点一次又切回来。

## 渲染频率

早期版本把 `maxFPS` 设在了 `app.ticker` 上，而页面用的是共享 ticker（`sharedTicker: true`），
所以那个上限其实**没生效**（日志里能跑到 300+ 帧）。

现在改成 **设置里的「渲染帧率上限」**（`fpsLimit`，默认 60，可选 30–240 或"不限制"），
由 `applyFpsLimit()` 同时设到 `PIXI.Ticker.shared` 和 `app.ticker` 上；实测上限 30 / 90 / 60 时
真实渲染帧数是 29 / 86 / 59 fps，"不限制"时 149 fps（见 README 的「性能实测」）。
另外 `countFrame()` 挂在共享 ticker 上自己数帧，设置页显示的"当前 fps"用的就是这个值 ——
PIXI 自带的 `ticker.FPS` 是平滑值，刚改完上限时会虚高（实测偏差能到 60%），不能直接拿来显示。

另外，早期版本为了让右键菜单更精准，每 120 ms 读一次画布像素 —— 那会让 GPU 流水线停顿，
也一并删掉了。
* 看不到形象时先确认：是不是被别的最上层窗口挡住了 / 是不是禁用了 WebView2 运行时
  （Windows 10/11 一般自带 "Microsoft Edge WebView2 Runtime"）。
* 启动器找不到 Python 时，设置环境变量 `CODEXPET_PYTHON` 指向 `python.exe` 即可。
